# Mermaid 与 Markdown 表格图卡渲染设计

## 目标

让编辑器中的 Mermaid 代码块与 GFM Markdown 表格在图卡预览和导出图片中渲染为实际内容，而不是普通代码或纯文本。

目标效果只包含流程图本体和排版后的表格，不复刻参考截图中的 Mermaid 工具栏、运行按钮、全屏按钮或表格复制按钮。

## 支持范围

- 识别语言为 `mermaid` 的围栏代码块。
- 支持 Mermaid `flowchart` 等由当前 Mermaid 运行库支持的图表语法。
- 识别 marked.js 在 GFM 模式下生成的 `table` token。
- 表格支持表头、正文、列对齐、单元格自动换行和动态行高。
- Mermaid 与表格同时用于编辑器预览、单张下载和批量下载。
- 浅色、深色模板均保持可读性。

不在本次范围内：交互式 Mermaid 控件、复制按钮、HTML 表格任意标签、跨页拆分单个 Mermaid 图、复杂单元格块级 Markdown。

## 架构与数据流

现有解析和绘制链路保持不变：

1. `TextSplitter` 使用 marked.js 将 Markdown 解析为 token。
2. `CanvasTextEngine` 将 token 转换成带精确宽高的布局对象。
3. 分页器依据布局对象高度决定当前图卡是否能容纳内容。
4. `CanvasRenderer` 将布局对象绘制到预览与导出 Canvas。

新增或修正的布局类型：

- `mermaid-block`：包含已加载的图像、绘制尺寸、内容高度和上下间距。
- `table-grid`：包含列宽、每行高度、单元格换行结果、对齐方式和整体高度。

解析层不生成最终 DOM。DOM 仅可作为 Mermaid SVG 生成过程中的临时测量载体，最终输出统一进入 Canvas。

## Mermaid 渲染

Mermaid 库在编辑器启动时加载，文本布局引擎必须等待其真正可用后再渲染。每个 Mermaid token 使用唯一 ID 生成 SVG。

渲染步骤：

1. 根据图卡模板选择可读的 Mermaid 主题。
2. 调用 Mermaid 生成 SVG。
3. 优先读取 SVG `viewBox`，其次读取明确的宽高属性，避免依赖隐藏 DOM 的零尺寸测量结果。
4. 将 SVG 转为浏览器可加载的图像对象。
5. 等比缩放至内容区宽度以内并水平居中。
6. 将实际缩放高度写入布局对象，使分页结果与绘制结果一致。

若图表高度超过一张图卡可用内容高度，则缩小到可用范围；不把同一个流程图拆到两张图卡。

## 表格布局与绘制

列宽根据表头和正文内容的测量宽度分配，同时设置最小列宽。总宽度固定为当前图卡内容区宽度。内容较长的列获得更多空间，但不能挤压其他列到不可读。

每个单元格先按其列宽完成内联文本布局，再根据该行中最高的单元格确定整行高度。表头使用更高字重，正文使用正常字重。列对齐遵从 Markdown 分隔行中的左对齐、居中和右对齐定义。

视觉采用适合图卡的简洁文档风格：

- 不绘制外部容器或操作控件。
- 使用克制的横向分隔线，避免沉重的全网格视觉。
- 表头与正文通过字重和轻微底色区分。
- 单元格保持足够的水平与垂直留白。
- 颜色从当前模板文字色和背景明暗派生。

表格优先整体放入当前页；放不下时移动到下一页。若完整表格高于单页可用区域，则按行拆分，并在续页重复表头，避免裁切或缩小到不可读。

## 错误处理

- Mermaid 库加载失败：绘制带简短说明的错误占位块，并在控制台保留详细错误。
- Mermaid 语法错误：显示“Mermaid 图表解析失败”，不回退为普通代码块。
- 空表格或异常 token：跳过无效布局并记录警告，不阻断其他图卡生成。
- SVG 图像加载失败：使用错误占位块，确保分页流程继续完成。

## 验证与验收

使用用户提供的 Embedding Cache 表格和核心工作流程 Mermaid 示例验证：

- Mermaid 在预览中显示为完整流程图，并出现在下载的 PNG 中。
- 图表保持比例、居中且不超出内容区域。
- 表格显示三列、表头加粗、五行数据完整，长技术名称不越界。
- 表格与后续段落之间有稳定间距。
- 内容在分页边界附近时不被裁切或重叠。
- 浅色与深色模板中文字、线条和背景均清晰可读。
- Mermaid 无效语法和库加载失败均产生可见错误占位。
- 现有标题、段落、代码块、数学公式和图片渲染不回归。

## 实施约束

在用户当前未提交修改的基础上做针对性修复，不覆盖或还原无关改动。Mermaid 依赖的交付方式沿用项目现有的静态页面架构；具体实现计划中需确认是否将依赖本地化，以避免仅依赖 CDN 时的离线失败。
